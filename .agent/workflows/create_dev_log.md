# 開発アップデートサマリーの作成ワークフロー

ユーザーから「開発はこれで一区切り」「アップデートサマリーを作成して」といった指示があった場合、以下の手順に従ってObsidianにDev Logを作成してください。

1. **直近の変更内容の把握**
   - どのような機能が追加・変更・修正されたかを、チャットやコミットログ等から抽出します。
   - 変更の意図、技術的な背景、ユーザーにもたらすメリットを整理します。

2. **Obsidianノートの作成**
   - 保存先パス: `C:\obsidian\Obsidian\Dev_Logs\update`
   - ファイル名: `YYYYMMDD_機能追加またはアップデート名.md` (例: `20260228_Obsidian_CLI機能統合.md`)
   - ツール: 手順に沿って `tool_create_note` を使用します。

3. **ノートのフォーマット**
   ノートは以下の構成でMarkdown形式で作成してください：

   ```markdown
   ---
   tags:
     - type/devlog
   created: YYYY-MM-DD
   ---

   # [アップデートのタイトル]

   > [!SUMMARY] 要約
   > 今回のアップデートの簡単な要約（1〜2行）

   ## 1. アップデート概要
   - [追加・変更された機能のリストと解説]

   ## 2. チュートリアル・使用例（該当する場合）
   - [新機能の具体的なプロンプト例や、どう使えばいいかのガイド]

   ## 3. 技術的な変更点（裏側）
   - [プロンプトの変更、システムプロンプトの調整、ファイル構成の変化など]
   ```

4. **保存と完了報告**
   - ノートを作成したら、該当ファイルが `C:\obsidian\Obsidian\Dev_Logs` フォルダ内に正しく保存されたことを確認します。
   - ユーザーにノートの作成が完了したことと、そのサマリーをDiscordまたはチャットで報告してください。
