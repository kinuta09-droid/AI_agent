# /grill — 厳格なアドバーサリアル・コードレビュー

直近の変更に対して、厳しいコードレビューを実施してください。あなたはプロジェクトの品質管理責任者です。

## レビュー手順

### 1. 変更の特定
```bash
git -C "C:\AI_agent" diff HEAD~1 --stat
git -C "C:\AI_agent" diff HEAD~1
```
直近のコミットで変更されたファイルと差分を確認する。

### 2. 正当性の検証
各変更について以下を問い詰める:
- **Why**: なぜこの変更が必要か？目的に対して最小限の変更か？
- **What if**: この変更がなかったら何が壊れるのか？
- **Alternatives**: 別のアプローチは検討したか？

### 3. エッジケースの洗い出し
変更された各関数/ロジックについて、最低3つのエッジケースを挙げる:
- 空入力 / null / None
- 極端に大きい入力
- 同時実行 / レースコンディション
- ネットワーク切断 / API タイムアウト
- ファイルパーミッション / エンコーディング

### 4. 既存テストとの整合性
```bash
dir C:\AI_agent\test_*.py
```
変更に関連するテストファイルが存在するか確認し、テストが壊れていないかチェックする。

### 5. セキュリティチェック
- ハードコードされた秘密情報がないか
- ユーザー入力のサニタイズは適切か
- ファイル操作のパス・トラバーサルリスクはないか

### 6. パフォーマンスチェック
- N+1 問題やループ内 API コールがないか
- 不要な再計算やメモリリークのリスクがないか

## 出力フォーマット

```
## 🔥 Grill Report — [コミットハッシュ]

### 致命的問題 (Must Fix)
- [問題と修正提案]

### 要改善 (Should Fix)
- [問題と修正提案]

### 提案 (Nice to Have)
- [改善案]

### 判定: ✅ PASS / ❌ FAIL
```

## バグ修正時の特別ルール
バグ修正のレビューでは、追加で以下を実行:
1. 修正が根本原因を解決しているか確認（症状だけの対処ではないか）
2. 同じパターンのバグが他の箇所にないか検索
3. 「この修正を捨てて、最もエレガントな解決策を一から実装し直してください」と提案
