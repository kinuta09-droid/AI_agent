# /techdebt — 技術的負債スキャナー

プロジェクト `C:\AI_agent` 内の技術的負債を検出し、リファクタリング提案を行ってください。

## 対象ファイル

`C:\AI_agent` 配下の `.py` ファイルを対象とする。以下は除外:
- `antigravity_env/` (仮想環境)
- `__pycache__/`
- `*.bak` ファイル

## 実行する分析（5項目）

### 1. デッドコード検出
- 各 `.py` ファイル内で `def` で定義されている関数を列挙する
- プロジェクト内の他のファイル（自身を含む）でその関数名が参照されているか `grep` で確認する
- **一度も参照されていない関数**をリストアップする
- ただし `main()`, `run_bot()`, `run_scheduler()` などのエントリーポイントは除外する

### 2. 重複・類似コード検出
- 複数ファイル間で似たロジック（同じAPIコール、同じファイル操作パターン）がないか確認する
- 特に以下のパターンに注意:
  - Gemini API呼び出しの重複ラッパー
  - ファイルI/O（Obsidian Vault書き込み）の繰り返しパターン
  - エラーハンドリングの不統一

### 3. TODO/FIXME/HACK コメント収集
- 全 `.py` ファイルから `TODO`, `FIXME`, `HACK`, `XXX`, `WORKAROUND` コメントを検索する
- ファイル名・行番号と共にリストアップする
- 各項目に「対応すべき優先度」を提案する

### 4. 未使用 import の検出
- 各 `.py` ファイルの `import` 行を抽出する
- インポートされたモジュール/関数名がファイル内で実際に使用されているか確認する
- 未使用の import をリストアップする

### 5. コード品質チェック
- `# -*- coding: utf-8 -*-` 宣言が先頭にないファイルを報告する
- ハードコードされたAPI キーやパスワードがないか確認する（`.env` を使うべき箇所）
- 関数の行数が100行を超えるものを「分割候補」として報告する
- `.bak` ファイルの数・最終更新日を報告し、クリーンアップを提案する

## 出力フォーマット

結果を以下の形式でまとめてください:

```
## 🔍 Tech Debt Report — [日付]

### 🔴 High Priority
- [項目と具体的な修正提案]

### 🟡 Medium Priority
- [項目と具体的な修正提案]

### 🟢 Low Priority
- [項目と具体的な修正提案]

### 📊 サマリー
- デッドコード: X 件
- 重複コード: X 箇所
- TODO/FIXME: X 件
- 未使用import: X 件
- 品質警告: X 件
- .bak ファイル: X 個（合計 XX KB）
```

## 完了後のアクション

1. 報告書の内容に基づき、修正を希望するか確認する
2. 修正する場合は、優先度 High の項目から順に対応する
3. 対応完了後、Git にコミットする
