# discord.py Bot: Views, Timeouts & Result Display

- **`discord.ui.View` の `timeout=None` は「Bot 再起動をまたいで生きる」宣言であって、単なる無期限ではない**。`bot.add_view()` での再登録とセットでなければ、再起動後はボタンが押しても無反応 (Discord 側に「インタラクションに失敗しました」が出るだけでログには一行も残らない = 無言の死)。おまけに discord.py の View ストアから永久に消えずメモリを食う。永続化の条件は **固定 custom_id + コールバックがステートレス** (毎回ファイルを読み直す) の2つで、instance 変数に作業状態を持つ View は原理的に永続化できない → その場合は**有限 timeout + `on_timeout` でボタンを無効化**する (`ClientReviewLoopView` / `OpenInObsidianView` を是正)。`tests/test_button_views.py` の静的スキャンが「timeout=None なのに add_view されていない View」を落とす
- `on_timeout` から `interaction.followup.send()` の戻り (WebhookMessage) を編集して期限切れを通知する場合、**View の timeout は interaction token の寿命 (発行から15分) より短くする**。15分ちょうどにすると通知の edit がトークン失効と同時になり、通知だけが無言で失敗する。なお `discord.ui.View` に `message` 属性は自動では入らない (自分で代入する)。`view.timeout = 秒数` は実行中のタイマーの期限も更新できるので、長時間処理の前後で延長/復帰させる
- 例外メッセージを整形し直すときは **`startswith("Error:")` で分岐している箇所を先に洗う**。`commands/bot_commands_agent._FAILURE_PREFIXES` はコロン固定だったため、`Error (RuntimeError): ...` 形式にすると失敗結果を成功扱いして次回 `/agent` のセッション文脈に混ぜるところだった
- **pending queue (検出→`pending.json`にslot登録→Discordへボタン付き通知→永続Viewがクリック処理) を新規実装するときは、「確定保存」を必ず「通知成功の後」にする**。`tools/tool_contradiction_resolve.py` の `queue_contradiction()` を新規実装した際、最初は `_save_pending(pending, ...)` (保存) → `_notify_contradiction(...)` (Discord送信) の順で書いた。grillレビューで指摘: `_notify_contradiction` がwebhook障害・レート制限等で例外を投げると、pending.jsonには既にslotが確定保存されているのにDiscord上にはボタンが一切表示されず、そのslotは「使用中」のまま誰も裁定できなくなる (押すボタンが無い)。`CONTRADICTION_SLOTS` は有限個 (5) なので、これが繰り返されるとスロットが徐々に埋まり、以降の新しい検出は「スロット満杯」として静かに拾われなくなる — 無言の死の亜種。参考にした既存実装 `tools/tool_note_promotion.py` の `run_note_promotion_job()` は「複数クラスタをループしながら都度通知するが `_save_pending` はループを抜けた後に1回だけ呼ぶ」設計 (個々の通知が例外を投げればループが止まり `_save_pending` に到達しない) になっており、同種のリークが起きない作りだった。今回は単一エントリだったため、この「全件成功してから一括保存」という設計意図に気づかず素朴に逆順で書いてしまった。修正は「通知→保存」に入れ替え、通知が例外を投げれば `FileLock` の `with` を抜けて呼び出し元まで伝播し `_save_pending` に到達しない形にした。**類似実装を型として真似るときは、処理順序を見た目だけでなく「なぜその順序か」まで読み取ってから流用する**。回帰は `tests/test_contradiction_resolve.py` (2026-08-22, master `8a28e29`)
